2. Responsibilities, ownership & delivery

What exactly was your role in the project?

“My responsibility was to take assigned requirements, understand the expected behaviour, implement the UI or API changes, connect the frontend and backend where required, validate the flow, fix issues and coordinate the work for review/deployment.” Follow this with two concrete tasks you personally completed.

Did you develop the project from scratch?

Be precise. “I developed some modules from scratch within an existing application” is different from “I built the entire product from scratch.” Explain whether you created the project setup, database schema, APIs, UI, deployment pipeline or only selected modules.

How do you understand a requirement before coding?

I clarify the user flow, input fields, validations, expected output, permissions, error cases and dependencies. I review designs or existing behaviour, break the work into smaller tasks, identify API/database changes and confirm unclear points before implementation.

How do you estimate development work?

I break the feature into UI, API, database, integration and testing tasks. I consider complexity, dependencies, unknowns and edge cases. I communicate assumptions and risks, then update the estimate if new requirements appear.

How do you work with other developers or teams?

I clarify API contracts and ownership, share progress and blockers, use version control and code reviews, and test integrations early. I try to communicate changes that may affect other modules rather than making assumptions.

How do you handle changing requirements?

I first understand what changed and why. Then I check the impact on existing behaviour, APIs, database and timeline. I discuss trade-offs with the team, update the implementation plan and test both the new flow and affected existing flows.

How do you explain a project when you cannot disclose client details?

“I cannot share confidential client or business information, but I can explain the application domain, the technical architecture at a high level, the modules I worked on and the challenges I solved.”

3. Frontend questions

How do you structure a React application?

I separate the application into pages/routes, reusable components, feature or module logic, API/service functions, hooks and shared utilities. I keep components focused, avoid duplicating logic and introduce shared state only when multiple parts of the UI need it.

How do you manage state in React?

For local UI state I use useState. For values that need to persist between renders but should not trigger rendering, I use useRef. I use Context for relatively shared state such as authentication or menu state. For server data, I keep fetching and caching concerns separate from local UI state and use the project's established data-fetching approach.

What is the difference between props and state?

Props are inputs passed from a parent component and should be treated as read-only by the child. State is data managed by a component (or a state owner) that can change over time and trigger a re-render.

How do you make a page responsive?

I use a mobile-first layout where practical, flexible widths, CSS Grid/Flexbox, responsive breakpoints and appropriately sized images. I test real viewport sizes and check navigation, forms, text wrapping, spacing and touch targets rather than relying only on desktop preview.

How do you improve frontend performance?

I measure first, then address the actual bottleneck. Common steps include optimizing image size and format, lazy-loading below-the-fold assets, prioritizing the main banner image, reducing unnecessary JavaScript, splitting code where useful, avoiding unnecessary re-renders and minimizing layout shifts.

How do you handle form validation?

I validate required fields, formats, lengths and business rules on the client for immediate feedback, and repeat validation on the server because client-side validation can be bypassed. I show field-level messages and handle loading, success and failure states.

What is the difference between useEffect and useMemo?

useEffect is for synchronizing a component with external systems, such as subscriptions, timers or imperative APIs. useMemo caches the result of a calculation between renders when its dependencies have not changed. I avoid using either without a clear need.

How do you handle API errors in the UI?

I handle network failures, non-success HTTP responses, validation errors and unexpected server errors separately where possible. I show a useful message, preserve user input when appropriate, prevent duplicate submissions and log enough context for debugging without exposing sensitive data.

How do you avoid duplicate API calls or form submissions?

I check component lifecycle and effect dependencies, cancel or ignore stale requests when appropriate, debounce search inputs, and disable the submit action while a request is pending. The backend should also protect important operations against duplicate requests where necessary.

4. Backend, Node.js, PHP & API questions

How does the frontend communicate with the backend?

The frontend sends HTTP requests to backend endpoints, usually using JSON for request and response data. The backend authenticates and validates the request, applies business rules, interacts with the database and returns an appropriate status code and response. The frontend then updates the UI based on the result.

What is REST API?

REST is an architectural style for designing network APIs around resources. Common HTTP methods include GET to read, POST to create or trigger processing, PUT/PATCH to update, and DELETE to remove. A well-designed API uses predictable URLs, suitable status codes, validation and consistent response formats.

What is middleware in Express or Laravel?

Middleware runs during the request-response lifecycle. It can inspect or modify a request, authenticate a user, check permissions, log activity or reject a request before it reaches the main handler. In Laravel, middleware is commonly used for authentication and route access checks; in Express it is a function in the middleware chain.

How do you organize backend code?

I separate routing, request validation, business logic and data access according to the framework and project size. In Laravel I use routes, controllers, Form Requests, models and services when useful. In Express I commonly separate routes, controllers, middleware and service/data-access logic. I avoid adding layers that do not provide a clear benefit.

How do you handle errors in an API?

I validate input early, use centralized error handling where supported, return appropriate HTTP status codes and avoid exposing stack traces or internal details to clients. I log diagnostic information on the server and keep API error responses consistent.

What is the difference between authentication and authorization?

Authentication verifies who the user is. Authorization determines what that authenticated user is allowed to do. For example, logging in verifies identity; checking whether the user has the Supervisor role before approving a claim is authorization.

How would you implement role-based access control?

I authenticate the user, retrieve their role or permissions, and enforce access on the backend for every protected action. The frontend can hide unavailable controls for usability, but it is not the security boundary. I would define permissions centrally and test both allowed and denied cases.

What is the Node.js event loop?

Node.js uses an event loop to coordinate JavaScript execution and asynchronous operations. It allows the process to handle I/O without blocking the JavaScript thread while waiting for operations such as network or file-system work. CPU-heavy synchronous work can still block the event loop, so it should be avoided or moved to an appropriate worker/process strategy.

What is the difference between synchronous and asynchronous code?

Synchronous code executes in sequence and the current operation must finish before the next one proceeds. Asynchronous code allows the program to continue while waiting for an operation to complete, using callbacks, Promises or async/await to handle the result later.

How do you secure an API?

I use HTTPS, secure authentication, authorization checks, server-side validation, parameterized database queries or ORM safeguards, rate limiting where appropriate, safe error responses, secure secret management and careful handling of uploaded files. I also avoid logging passwords, tokens or sensitive personal data.

How do you handle file uploads?

I validate file size, allowed file types and content, generate safe server-side filenames, restrict upload access, store files outside executable/public paths when appropriate and enforce authorization for downloads. I also consider malware scanning and storage limits based on the application's risk.

5. Database & SQL questions

How do you design a relational database?

I identify entities, their attributes and relationships, define primary and foreign keys, choose appropriate data types and constraints, and normalize the schema to reduce unnecessary duplication. I then consider indexes and query patterns based on how the application reads and writes data.

What is a primary key and a foreign key?

A primary key uniquely identifies a row in a table. A foreign key references a key in another table and enforces referential integrity between related records.

What is the difference between INNER JOIN and LEFT JOIN?

INNER JOIN returns rows with matching records in both tables. LEFT JOIN returns every row from the left table and matching rows from the right; if there is no match, right-side columns are NULL.

What is database normalization?

Normalization organizes data to reduce duplication and update anomalies. For example, instead of repeating a category name in every product row, products can reference a category table through category_id. I balance normalization with practical query and performance needs.

What is an index and when would you use one?

An index helps the database find rows more efficiently for supported query patterns, such as filtering or joining on frequently used columns. Indexes consume storage and add write overhead, so I create them based on query plans and real usage rather than indexing every column.

How do you prevent SQL injection?

I use parameterized queries or the framework's safe query builder/ORM features. I do not concatenate raw user input into SQL strings. I also validate input and apply least-privilege database permissions.

What is a database transaction?

A transaction groups related database operations into one unit. It follows ACID principles: atomicity, consistency, isolation and durability. For example, if a workflow updates two related records, a transaction helps ensure both changes succeed or neither is committed.

How would you handle pagination?

For straightforward admin lists, I use limit/offset or the framework's pagination support, return the current page and total information needed by the UI, and apply stable ordering. For very large or frequently changing datasets, cursor/keyset pagination may perform better.

How do you troubleshoot a slow database query?

I reproduce the query, inspect its execution plan, check filters and joins, verify indexes, look for unnecessary columns or N+1 queries, and measure before and after changes. I also check whether the delay is actually in the database or elsewhere in the request.

6. Authentication & security

How does session-based authentication work?

After successful login, the server creates a session and sends the browser a session identifier, commonly in a cookie. The browser sends that cookie on subsequent requests and the server uses it to identify the session. Secure cookie settings, session expiry and CSRF protection are important.

How does JWT authentication work?

After verifying credentials, the server issues a signed token containing claims such as the user identifier and expiry. The client sends it with later requests, and the server verifies its signature and claims. JWTs need careful expiry, storage and revocation strategy; a signed JWT is not automatically encrypted.

Where should passwords be stored?

Passwords should never be stored in plain text. They should be hashed using a password-hashing algorithm designed for this purpose, such as bcrypt or Argon2, with appropriate parameters. Encryption is not a substitute for password hashing.

What is CORS?

Cross-Origin Resource Sharing is a browser security mechanism that controls whether a page from one origin can access resources from another origin. The server must return the appropriate CORS headers. CORS is not authentication and does not replace backend access control.

What is CSRF?

Cross-Site Request Forgery tricks a browser into sending an unwanted authenticated request to a site. Defences include CSRF tokens, SameSite cookie settings and checking request origin where appropriate. The exact approach depends on the authentication method and framework.

7. Challenges, testing & deployment

What was the most challenging issue you faced?

Choose a real issue. Explain the symptom, how you reproduced it, what you inspected, the root cause, the fix and how you verified it. A strong answer demonstrates your debugging method, not just that the issue was difficult.

One type of issue I have handled is a responsive layout or form flow behaving differently across screen sizes/browsers. I reproduced the issue, inspected the relevant CSS and JavaScript, isolated the conflicting rule or event flow, applied a targeted fix and retested the affected viewports and submission path.
How do you debug a production issue?

I first understand impact and scope, check recent changes and available logs, reproduce safely if possible, and isolate whether the issue is frontend, API, database or infrastructure. I prioritize restoring service safely, verify the fix and document the root cause and prevention steps.

How do you test your code?

I test the expected flow and edge cases manually, check validation and error states, and use automated tests where the project has them. For APIs I verify status codes, response data, authorization and invalid input. I also check that existing functionality has not regressed.

What is the difference between unit, integration and end-to-end testing?

Unit tests check a small unit in isolation. Integration tests check whether multiple parts work together, such as a controller and database layer. End-to-end tests exercise a complete user flow through the application, such as logging in and submitting a form.

How do you use Git in a team?

I work on a feature or bug-fix branch, make focused commits, pull or rebase according to team practice, resolve conflicts carefully and raise a pull request for review. I avoid committing secrets and try to keep changes small enough to review.

What happens when you deploy a web application?

At a high level, code is built or prepared for production, environment variables and secrets are configured, database migrations are applied safely, static assets are served, the application process is started or restarted, and logs/health are checked. The exact deployment process depends on the hosting setup and team pipeline.

How do you handle a bug that you cannot immediately solve?

I narrow it down, gather logs and reproduction steps, test one hypothesis at a time and consult documentation or teammates when needed. I communicate the impact and progress rather than silently spending too long. Once fixed, I add a regression test or documented check if appropriate.

8. Project-specific examples to prepare

Use these as preparation templates. Only describe a project as professional work if it really was part of your job.

Explain a healthcare website or lead-generation project.

Purpose: Present healthcare/treatment information and let visitors submit enquiries.

Possible responsibilities to mention if accurate: Responsive page development, reusable sections, form validation, AJAX/API submission, tracking parameters, SEO/performance improvements and cross-device testing.

Likely follow-ups: How did you validate a phone number? How did you prevent duplicate submissions? How were source/campaign values captured? How did you optimize the banner image? What happened if the API failed?

Answer frame: “I worked on the frontend experience and enquiry flow. I implemented [specific pages/components], handled [specific validation/integration], and addressed [real issue].”

Explain a claims management application.

Purpose: Manage insurance/health claims through defined user roles and processing stages.

Possible modules: User login, roles such as Superadmin/Supervisor/Field Officer/Data Entry, claim creation, claim type configuration, assignment, status updates, file attachments and paginated lists.

Technical discussion: Laravel routes/controllers/models/migrations, MySQL foreign keys, validation, middleware or policies, relationships and transactions.

Answer frame: “In my practice implementation, I modelled users, roles, claim types and claims. I focused on relational data, role-based access and the claim lifecycle. I would explain the workflow and the backend checks that prevent users from performing actions outside their role.”

If this is not deployed professional work, explicitly call it a personal or practice application.

Explain an e-commerce or product administration panel.

Purpose: Allow administrators to manage categories, subcategories and products.

Possible features: Product CRUD, SKU and price validation, category relationships, optional subcategory, status management and list pagination.

Technical discussion: Laravel migrations, Eloquent relationships, validation rules, foreign-key delete behaviour, form handling and database constraints.

Answer frame: “I built a practice admin module to manage product data. The key learning areas were relational modelling, validation and keeping category/subcategory references consistent.”

Explain a real-time chat application.

Purpose: Allow authenticated users to exchange messages in real time.

Possible architecture: React UI, Node.js/Express API, Socket.IO for live events, and a database for users/conversations/messages.

Technical discussion: Authentication during socket connection, joining authorized rooms, mapping users to sockets, message persistence, reconnect behaviour and access control.

Answer frame: “In a practice project, I explored real-time messaging using Socket.IO. I worked through how authenticated users connect, how conversations/rooms are selected and how messages are delivered and stored.”

Explain a ride-hailing database design.

Purpose: Model the main entities behind a ride-booking service.

Possible entities: Users, drivers, vehicles/cabs, cab types, rides, payments and ratings.

Technical discussion: PostgreSQL primary/foreign keys, one-to-many relationships, ride status lifecycle, constraints, indexes and transaction boundaries.

Answer frame: “I designed a practice relational schema for a ride-hailing use case. I focused on entities and relationships first, then considered constraints and how a ride moves through requested, accepted, in-progress and completed states.”

What if the interviewer asks for a project you personally enjoyed?

Choose the project where you can explain the most detail. Say why it was interesting: a tricky integration, a workflow you designed, performance work, database relationships or a feature you owned. Avoid choosing a project only because its technology sounds impressive.

10. A simple structure to remember

Project answer formula:
1. Project purpose — what problem did it solve?
2. Users — who used it?
3. Stack — what technologies were used?
4. Your ownership — what did YOU implement?
5. Challenge — what problem did you solve?
6. Result — what improved or what was delivered?

Final advice: Prepare two professional projects in depth and one personal project that demonstrates backend/full-stack ability. Know the request flow, database tables, authentication approach, one difficult bug and your exact contribution for each.
